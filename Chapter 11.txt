############################################################
## CONTEXT
############################################################

VERVE is a Windows-native AI Operating Companion.

It should interact with Windows in the same way an experienced user can—but faster, more consistently, and with appropriate safeguards.

Automation should enhance productivity while respecting user control, security, and privacy.

====================================================================================================

############################################################
## PRIMARY OBJECTIVE
############################################################

Provide secure, reliable, and extensible automation for:

• Windows
• Installed applications
• Files
• Browsers
• Devices
• Background services
• Local networks
• Developer tools

without compromising system stability.

====================================================================================================

############################################################
## AUTOMATION LAYERS
############################################################

Layer 1

Native Windows APIs

↓

Layer 2

Application Integrations

↓

Layer 3

UI Automation

↓

Layer 4

Browser Automation

↓

Layer 5

Workflow Orchestration

↓

Layer 6

Multi-Agent Coordination

Monitor hardware

Manage clipboard

Take screenshots

Manage windows

Move windows

Virtual desktops

Notifications

Power options

Lock workstation

Sleep

Restart

Shutdown (confirmation required)

############################################################
## WORKFLOW ENGINE
############################################################

Users should be able to describe workflows naturally.

Example:

"When I start work:

Open Outlook

Launch Visual Studio

Open the VERVE project

Start Docker

Open documentation

Set Teams to Available"

VERVE should convert this into a reusable automation workflow.

====================================================================================================

############################################################
## SELF-HEALING AUTOMATION
############################################################

If an automation step fails:

Determine the reason.

Retry when appropriate.

Select an alternative method if available.

Resume from the point of failure.

Avoid restarting the entire workflow unnecessarily.

############################################################
## SECURITY MODEL
############################################################

Classify operations by privilege.

Examples:

Low Risk

Open application

Medium Risk

Modify user files

High Risk

Registry changes

Install software

Critical Risk

Delete large volumes of data

Shutdown

Firmware updates

Higher-risk actions require stronger confirmation or elevated permissions.

====================================================================================================

############################################################
## USER APPROVAL
############################################################

Users may define trust levels.

Examples:

Always Ask

Ask Once Per Session

Always Allow for Approved Categories

Never Allow

Approval policies should be configurable per capability.

====================================================================================================

############################################################
## ACCEPTANCE CRITERIA
############################################################

Implementation is complete only if it:

✓ Controls Windows reliably.

✓ Supports reusable workflows.

✓ Handles failures gracefully.

✓ Integrates with the agent system.

✓ Reports progress.

✓ Preserves security.

✓ Minimizes unnecessary user interaction.

====================================================================================================

############################################################
## COMMON FAILURE MODES
############################################################

Avoid:

Blind UI clicking.

Ignoring permission failures.

Infinite retry loops.

Unsafe destructive operations.

Blocking the conversation while automation runs.

Hardcoding screen coordinates.

====================================================================================================

############################################################
## CODE GENERATION CONSTRAINTS
############################################################

Generated implementations must:

Separate automation providers from business logic.

Support dependency injection.

Abstract operating-system APIs.

Provide structured logging.

Allow plugin-based automation providers.

Remain testable without requiring physical user interaction where possible.

====================================================================================================

############################################################
## ABSOLUTE RULE
############################################################

VERVE should interact with Windows intelligently.

Automation should feel deliberate, reliable, transparent, and recoverable.

The objective is not merely to simulate user input.

The objective is to become an intelligent operating companion capable of choosing the safest and most effective method for every task.
