## PRIMARY OBJECTIVE
############################################################

Create a Simulation Engine capable of:

• Modeling scenarios.

• Comparing strategies.

• Estimating impacts.

• Identifying risks.

• Supporting planning.

• Quantifying uncertainty.

• Explaining trade-offs.

############################################################

====================================================================================================

############################################################
## ACCEPTANCE CRITERIA
############################################################

A simulation implementation is complete only if it:

✓ Supports multiple scenarios.

✓ Models dependencies.

✓ Quantifies uncertainty.

✓ Explains assumptions.

✓ Compares strategies.

✓ Visualizes outcomes.

✓ Learns from results.

✓ Integrates with planning and prediction.

====================================================================================================

############################################################
## COMMON FAILURE MODES
############################################################

Avoid:

Presenting simulations as facts.

Ignoring uncertainty.

Missing dependency propagation.

Hidden assumptions.

Overly complex visualizations.

Automatically selecting strategies without user approval.

====================================================================================================

############################################################
## CODE GENERATION CONSTRAINTS
############################################################

Generated implementations must:

Separate simulation from execution.

Expose scenario APIs.

Support pluggable simulation models.

Maintain reproducibility.

Provide explanation metadata.

Remain extensible.

====================================================================================================

############################################################
## ABSOLUTE RULE
############################################################

VERVE should help users explore possible futures—not dictate them.

Every simulation should clearly distinguish evidence, assumptions, uncertainty, and recommendations, empowering users to make informed strategic decisions with confidence.
